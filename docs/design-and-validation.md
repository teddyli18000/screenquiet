# 设计与验证记录

本文说明 ScreenQuiet 的关键实现选择、遇到的 Windows 显示配置问题，以及现有验证能支持到什么程度。文中只记录脱敏后的行为摘要，不发布原始本机日志、用户目录、精确时间、设备 ID 或进程标识。

## 设计

### 热键来源与百应启动桥

程序订阅 `root\WMI` 的 `LENOVO_UTILITY_EVENT`，只处理 `PressTypeDataVal = 1`。这样可直接按设备报告的 Fn+F9 事件控制切换，不依赖百应界面先启动。为避免该热键继续弹出百应界面，安装脚本针对 `LenovoBaiyingLauncher.exe` 和 `LenovoBaiying.exe` 的固定完整路径设置 IFEO 过滤，桥程序位于受保护的 Program Files 目录。

启动桥检查由 WMI 事件打开的 3 秒门控。命中门控的启动被抑制；普通启动会连同原参数转发，并在目标程序开始执行前解除调试状态。启动桥每次最多等待约 400 ms 检查门控，所以普通启动可能略有延迟；热键门控期间手动启动匹配目标也可能被抑制。安装前会拒绝已有 IFEO 配置，避免覆盖其他软件的设置。

### 虚拟显示与恢复

进入模式时先保存原显示快照，再添加虚拟显示器。程序要求起始布局恰好只有一个内置屏；它验证只含新建 Parsec 虚拟屏的候选布局，再应用该布局，使桌面在 Windows 显示拓扑中迁移到虚拟屏。若检测到其他显示路径或并发拓扑改变，会拒绝操作或恢复并退出，避免接管扩展屏配置。

每次切换都会在应用布局前保存恢复快照。退出路径会尝试还原快照；独立恢复进程在控制程序退出或 20 秒没有收到心跳后也会尝试恢复。程序请求系统保持唤醒，锁定、休眠等会话状态变化会触发恢复。代码中的恢复机制降低了挂起风险，但没有替代真实故障注入验证。

### 物理输入来源筛选

空闲期间不注册 Raw Input；进入关屏模式时才监听键盘、鼠标和触控板。事件处理只判定是否有键盘按下、鼠标移动或按键、触控板新接触，不保存键值、文本、位置或触控报告。Fn+F9 的按键释放本身不作为唤醒动作，切换后 0.9 秒内的输入也会忽略。

设备路径会映射到 Windows PnP 设备节点并沿祖先检查来源。`ROOT`、`SWD`、`UUYC` 及未知或无法解析的来源不被视为物理输入；代码识别 ACPI、I2C、USB 和 Bluetooth 总线来源。设备枚举和驱动差异仍可能导致个别真实设备无法识别，因此控制程序在没有识别到物理键盘时不会启用关屏。

## Windows 显示配置踩坑

实现先查找 Windows 已激活的 Parsec 候选路径，并沿用该路径已有的 mode 数据进行校验。只有这个分支不可用时，才尝试备用的未配置 path。Windows 会拒绝备用候选中的零值字段，因此代码把无效 rotation 补为 `DISPLAYCONFIG_ROTATION_IDENTITY (1)`，把零 scaling 补为 `DISPLAYCONFIG_SCALING_PREFERRED (128)`；这个 path-only 调用使用 `modeCount = 0` 和 `modes = null`。候选通过 `SDC_VALIDATE` 后才应用。

关键在于先尝试复用活动候选；只有备用未配置 path 才用 identity / preferred 默认值和零 mode 数量。对 path-only 调用传入非空 mode 数组，或保留无效的零值字段，会造成看似驱动已创建但显示切换仍被 Windows 拒绝。实现也只移除本次新建的 Parsec 虚拟屏，不清理既有显示设备。

## 验证记录

目标设备为 **Lenovo ThinkBook16 G7+ IAH，Windows 11 x64 build 26200**。参考构建使用 Windows 自带 .NET Framework C# 5 编译器；控制 EXE 大小为 47,104 字节。硬件与系统版本以外的设备不在当前验证范围内。

### 安装阶段的软件检查

`Finish-Setup.ps1` 的启动桥探针覆盖了原参数转发、目标代码开始前解除调试、热键门控抑制，以及同名但路径不同的程序不受过滤。安装脚本随后执行被动启动检查，检查 WMI 订阅、Raw Input 注册与释放等初始化路径。该流程不应用关屏显示布局，也不触发实际 Fn+F9 操作。

另有一次不应用布局的虚拟屏候选校验：驱动创建虚拟屏后，内置屏仍处于活动状态，虚拟屏专用候选通过 `SDC_VALIDATE`。

### 用户操作记录

- 一次本地按键尝试中，Fn+F9 进入关屏模式；物理键盘输入触发恢复，回到原显示布局。对应日志没有显示激活或恢复错误。
- 一次 UU 联调中，关屏模式持续约 55 秒，直到物理键盘输入后恢复。该次记录没有显示提前退出、显示目标冲突或错误；用户当时未发现异常。

这些摘要只说明上述单次运行完成了预期的状态转换。日志不能独立证明联调期间每一种 UU 远程输入类型都已测试，也不能证明物理面板全程实际熄灭；`SDC_VALIDATE` 通过也只代表候选布局被 Windows 接受校验。

## 尚未验证

鼠标和触控板唤醒、重启后的恢复、长时间运行、真实崩溃或恢复故障、不同物理设备与其他 Lenovo 型号尚未实测。当前记录也不证明其他远程输入注入方式会被识别或排除。公开发布时应将其描述为针对参考机型的实验性工具，而不是通用显示或远程输入兼容方案。
